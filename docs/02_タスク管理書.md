## 1. 進め方

- 4 つのマイルストーンに分割し、各マイルストーン終了時に **動くものをデモ** して次へ進む。
- 見積もりは「理想日(集中して作業した場合の日数)」。担当 1 名を前提。
- ステータス: `TODO` / `DOING` / `REVIEW` / `DONE` / `BLOCKED`
- 各タスクは GitHub Issue に起票し、本表の ID を Issue タイトルの先頭に付ける(例: `[M1-03] ソース定義YAMLの読込`)。

## 2. マイルストーン

| MS | 名称 | ゴール | 目安 |
|---|---|---|---|
| M0 | 準備 | アカウント・キー・基盤が揃い、Hello World が配信できる | 2 日 |
| M1 | 収集 | 全初期ソースから新着が Firestore に溜まる | 5 日 |
| M2 | 要約・配信 | 毎朝 2 チャネルにダイジェストが自動配信される | 5 日 |
| M3 | 品質・運用 | 監視・通知・再実行・監査が揃い、本番運用開始 | 4 日 |
| M4 | 拡張(任意) | 承認モード、速報配信、管理 UI | 5 日 |
