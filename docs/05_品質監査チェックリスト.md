## なぜやるのか

AI が生成した要約をそのまま配信しています。プログラムによる品質ゲート(出典 URL の実在確認など)は
機械的な誤りしか防げません。**「出典には書いていないことが書かれている」「数字が違う」といった
意味の誤り**は人が見るしかありません。週 1 回の抜き取りで、その兆候を早期に見つけます。

---

## 手順

### 1. 対象を選ぶ(1 分)

各チャネルから直近 7 日分のうち **重要度が高い項目を 5 件ずつ**、計 10 件。

```bash
pnpm cli preview --date 2026-09-08
pnpm cli preview --date 2026-09-09
# ... 直近 7 日分
```

### 2. 1 件ずつ照合する(7 分)

配信された項目と、その出典ページを並べて確認します。

| # | 確認項目 | 判定基準 |
|---|---|---|
| A1 | 出典リンクが開くか | 開く。404 やログイン要求でない |
| A2 | 出典が一次情報か | 官公庁・自治体の公式ページ。ニュースサイトの転載になっていない |
| A3 | 見出しが内容と合っているか | 出典の表題と主旨が一致。誇張や断定の追加がない |
| A4 | 要点が出典に書かれているか | **要約中の事実がすべて出典内に存在する**。書かれていないことが足されていない |
| A5 | 日付・金額・数値が原文どおりか | 施行日、期限、単価、加算率などが一字一句一致 |
| A6 | 「対象」が妥当か | 影響を受けるサービス種別が正しい。自治体情報に地域名が入っている |
| A7 | 助言・評価が混ざっていないか | 「〜すべき」「おすすめ」などの表現がない。事実の要約に徹している |
| A8 | 重要度の順序が妥当か | 報酬改定・法改正が上、イベント告知が下 |

## 監査に使えるデータ

生成に使った元記事・プロンプト・モデル応答は Firestore の `digests` に **90 日間** 保存されています(FR-16)。

```bash
# 特定の日のダイジェストを詳細に見る
gcloud firestore documents describe \
  "projects/$PROJECT/databases/(default)/documents/digests/welfare_2026-09-12"
```

保存されているフィールド:

| フィールド | 監査での使い道 |
|---|---|
| `entries` | 配信された各項目 |
| `excluded` | 品質ゲートで除外された項目と理由。除外が多すぎないか確認する |
| `prompt` | AI に渡した入力。要約が誤っていたとき、入力が足りなかったのか AI の誤りかを切り分ける |
| `rawResponse` | AI の生応答 |
| `usage` | トークン使用量。コスト監視(NFR-04) |
| `coverage` | 巡回できたソース数 |
