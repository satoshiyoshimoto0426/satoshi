`scripts/set-secrets.sh` が聞いてくる 4 つの値を、どこでどう取るかをまとめています。
**この作業は 1 回だけです。** 一度入れれば、あとは毎朝自動で配信されます。

---

## 0. 全体像 ― 「トークン」とは何か

このシステムは、人間の代わりにプログラムが LINE へ投稿します。
プログラムは人のようにログインできないので、代わりに **「このアカウントとして投稿してよい」
ことを証明する長い文字列** を LINE に提示します。これが **チャネルアクセストークン** です。

```
毎朝 07:30
  プログラム ──「この文字列を持っています」──→ LINE のサーバー
                                                 ↓ 確認OK
                                        あなたの公式アカウントから全友だちへ配信
```

- **パスワードと同じ重さ**の情報です。持っている人は誰でもあなたの公式アカウントとして
  投稿できてしまいます。チャットやメールに貼らず、GitHub にも置かないでください。
- このシステムでは Google Cloud の **Secret Manager** という金庫にだけ保管します。
  `set-secrets.sh` は、画面にも操作履歴にも残さずに金庫へ入れるためのものです。

必要な値は 4 つです。

| # | 値 | どこで取るか | 必須 |
|---|---|---|---|
| 1 | LINE チャネルアクセストークン(AIリスキリング制度情報局) | LINE Developers | 必須 |
| 2 | LINE チャネルアクセストークン(就労支援、放課後デイ情報局) | LINE Developers | 必須 |
| 3 | Anthropic API キー | Anthropic Console | 必須 |
| 4 | Slack Incoming Webhook URL | Slack | 必須(§4 に代替あり) |

---

## 1. LINE チャネルアクセストークン(2 つ分)

**公式アカウント 1 つにつき 1 本**必要です。2 アカウントあるので、以下を 2 回繰り返します。

### 1-1. Messaging API を有効にする(まだの場合)

LINE 公式アカウントは作っただけでは外部プログラムから投稿できません。
**Messaging API を有効化**する必要があります。

1. [LINE Official Account Manager](https://manager.line.biz/) にログインし、
   対象の公式アカウントを選びます。
2. 右上の **設定** → 左メニューの **Messaging API** を開きます。
3. **「Messaging APIを利用する」** をクリックします。
4. **プロバイダー** の選択・作成を求められます。
   - プロバイダーとは「開発者・事業者のまとまり」を表す入れ物です。
   - 会社名や屋号を入れて新規作成すれば問題ありません。
   - **2 つのアカウントで同じプロバイダーを使って構いません**(管理が楽になります)。
5. 内容を確認して **同意する** をクリックします。

> **プロバイダーは後から変更できません。** 作成前に名前をよく確認してください。

参考: [LINE公式アカウント Messaging APIマニュアル(LINEヤフー for Business)](https://www.lycbiz.com/jp/manual/OfficialAccountManager/account-settings_messaging_api/)

### 1-2. チャネルアクセストークン(長期)を発行する

Messaging API を有効化すると、開発者向けの管理画面に **チャネル** が作られます。
トークンはそちらで発行します。

1. [LINE Developers コンソール](https://developers.line.biz/console/) にログインします
   (公式アカウントと同じ LINE アカウントで入ってください)。
2. 1-1 で作った **プロバイダー** をクリックします。
3. 対象の **チャネル**(公式アカウント名で表示されます)をクリックします。
4. 上部のタブから **Messaging API設定** を開きます。
5. 画面をいちばん下までスクロールすると **チャネルアクセストークン(長期)** の欄があります。
6. **発行** ボタンを押します。長い英数字の文字列が表示されます。
7. コピーボタンでコピーします。**これがトークンです。**

> 一度画面を離れても、同じ場所で再表示・再発行できます。
> 再発行すると古いトークンは使えなくなるので、運用開始後は §5 のローテーション手順に従ってください。

参考: [チャネルアクセストークン | LINE Developers](https://developers.line.biz/ja/docs/basics/channel-access-token/) /
[Messaging APIを始めよう | LINE Developers](https://developers.line.biz/ja/docs/messaging-api/getting-started/) /
[長期アクセストークンの発行・確認方法](https://poster.ooo/howto/check-access-token/)

### 1-3. どちらのアカウントのトークンかを間違えない

`set-secrets.sh` は次の順で聞いてきます。**取り違えると配信先が入れ替わります。**

```
1 番目: LINE チャネルアクセストークン(AIリスキリング制度情報局)
2 番目: LINE チャネルアクセストークン(就労支援、放課後デイ情報局)
```

2 つを別々のメモ帳に分けて開き、貼り間違えないようにしてください。
貼り付けた文字は画面に表示されません(正常です)。そのまま Enter を押します。

### 1-4. 料金プランを確認する

友だち 20 名に毎日 1 通で、1 アカウントあたり月およそ 620 通になります。
無料のコミュニケーションプランは月 200 通なので**足りません**。
LINE Official Account Manager の **設定 → 利用と請求** から、
**ライトプラン以上**への変更が必要です(タスク M3-10)。

> 通数の上限と料金は LINE 側で改定されることがあります。契約時に最新の料金表をご確認ください。

## 2. Anthropic API キー

毎朝のまとめを書く AI の利用キーです。

1. [Anthropic Console](https://console.anthropic.com/) にログインします。
2. 左メニューの **API Keys** を開きます。
3. **Create Key** を押し、名前を付けて作成します(例: `seido-watch`)。
4. 表示されたキーをコピーします。`sk-ant-` で始まる長い文字列です。

> **このキーは作成直後の 1 回しか表示されません。** 閉じる前に必ずコピーしてください。
> 紛失した場合は古いキーを削除して作り直します。

支払い方法の登録も必要です(**Settings → Billing**)。
このシステムの想定使用量は月あたり数百円〜千数百円程度です(要件定義書 NFR-04)。

## 3. Slack Incoming Webhook URL

障害や除外の通知を受け取る先です。「この URL に送れば、この Slack チャンネルに投稿される」
という専用の宛先で、これ自体が秘密情報です。

1. [Slack API のアプリ一覧](https://api.slack.com/apps) を開き、**Create New App** を押します。
2. **From scratch** を選び、アプリ名(例: `制度改正ウォッチ`)と、通知を受けたい
   **ワークスペース**を選んで作成します。
3. 左メニューの **Incoming Webhooks** を開き、スイッチを **On** にします。
4. 下部の **Add New Webhook to Workspace** を押し、投稿先チャンネルを選んで **許可する**。
5. 生成された **Webhook URL** をコピーします。`https://hooks.slack.com/services/...` の形です。

---

## 4. Slack を使わない場合

`set-secrets.sh` は Slack Webhook も必須として聞いてきます。
Cloud Run Jobs がジョブ作成時に「値が入っていること」を検証するため、
1 つでも空だとデプロイが失敗するからです。

Slack を使わない運用にする場合は、**ダミー値を入れないでください。**
通知が失敗していることに気づけなくなります。代わりに、
`infra/terraform/main.tf` の 3 つのジョブ定義から `SLACK_WEBHOOK_URL` の行を削除してください。

その場合、障害の通知は Cloud Logging と Cloud Monitoring のアラート
(メール通知など)だけになります。

## 5. 取得後にすること

4 つの値が揃ったら、運用手順書 §6.1 の手順で Google Cloud Shell から投入します。

```bash
bash scripts/set-secrets.sh
```

投入後は、手元のメモからトークンを消してください。
値は Secret Manager に入っており、必要になれば同じスクリプトで入れ直せます。

**トークンを貼ってよい場所・いけない場所**

| 場所 | 可否 |
|---|---|
| `scripts/set-secrets.sh` の入力 | ○(画面にも履歴にも残りません) |
| Google Cloud の Secret Manager | ○ |
| チャット・メール・チケット | × |
| GitHub(コード、Issue、Actions の設定) | × |
| `.env` ファイルをコミット | × |

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| LINE Developers にチャネルが見当たらない | 公式アカウントと違う LINE アカウントでログインしている。ログインし直す |
| 「Messaging APIを利用する」が見当たらない | 既に有効化済み。LINE Developers 側でトークンを発行する(1-2) |
| トークン欄が空で「発行」ボタンがある | 未発行の状態。押せば発行される(正常) |
| 貼り付けても画面に何も出ない | 正常。伏せて入力しているだけ。そのまま Enter |
| Anthropic のキーを控え忘れた | 再表示はできない。古いキーを削除して作り直す |
| 配信先が入れ替わっている | 1-3 の取り違え。`set-secrets.sh` を再実行して正しい値を入れ直す |
